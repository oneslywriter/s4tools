A deleted clip keeps coming back on the S-4

You delete a track's sample on the Torso S-4 and save. The next time the project loads, or you return to that scene, the clip is back. Settings save fine; only the audio returns.

Why it happens

Deleting the sample removes its name from the project's project.json, but the audio file can stay in the project folder. The S-4 appears to find a track's audio by its file name, built from the scene and track number, so it loads the leftover file again.

PROJECTS/ └─ MY SONG.s4project/ ├─ project.json scene 7, track 1: no sample (deleted) ├─ discs/ │ ├─ scene1_track1.wav │ └─ scene7_track1.wav ← left behind, loaded again └─ tapes/

A DISC track's file is discs/scene<N>_track<T>.wav; a POLY track's is tapes/scene<N>_track<T>_poly.wav. TAPE recordings are stored differently and aren't part of this.

Fix it by hand

  1. Put the S-4 in USB storage mode. Its drive appears on your computer.
  2. Back up: copy the project's folder, PROJECTS/<NAME>.s4project, to your computer.
  3. Find the file for the scene and track that keeps coming back. Scene 7, track 1 on a DISC is discs/scene7_track1.wav.
  4. Move that file out of the project folder, onto your computer. Keep it until you've checked the result.
  5. Eject the drive, leave storage mode and restart the S-4.
  6. Load the project and go to that scene. The track should stay empty. If you turned it all the way down as a workaround, turn it back up and save.

One check first. With KEEP SAMPLE on, a track in another scene can play this same file. If that track still needs it, leave the file where it is. The tool below checks this for you.

Fix it with s4doctor

s4doctor.py is a small Python 3 script, nothing to install. It reads every project, lists the leftover files, and only moves the ones no track still uses. It never deletes anything.

  1. Download s4doctor.py and open a terminal in the folder you saved it to.
  2. Put the S-4 in USB storage mode.
  3. See what it finds. Use the drive letter or name your computer gives the S-4 (on a Mac, python3 and a path under /Volumes):
    python s4doctor.py "D:/PROJECTS"
  4. Move the leftovers into a folder on your computer. Each file's original place is written to moved.txt in that folder:
    python s4doctor.py "D:/PROJECTS" --move-to "C:/s4-moved"
  5. Run step 3 again. It should report 0 ghost files.
  6. Eject the drive, leave storage mode, restart the S-4 and check the scene.

To undo, copy a file back to the place listed in moved.txt, with the S-4 in storage mode.

To keep one, point the tool at a single project ("D:/PROJECTS/MY SONG.s4project") or move just the files you want by hand: it moves every leftover it finds in the folders you give it.

Seen on the S-4 with OS 2.x. The script also lists audio files that no track points at, for information.
